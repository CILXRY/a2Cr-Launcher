# 目录结构

## 1. 完整布局

```text
%USERPROFILE%\.a2CrLauncher\            ← A2CR_ROOT 可整体覆盖
├─shared\                               ← 与实例无关的内容；除 cache 外基本只读
│  ├─assets\
│  │  ├─indexes\<index_id>.json
│  │  └─objects\<hash[:2]>\<hash>
│  ├─libraries\<group path>\<artifact>-<ver>[-<classifier>].jar
│  ├─log_configs\<id>
│  ├─versions\
│  │  ├─<version_id>\
│  │  │  ├─<version_id>.json             ← 版本元数据（完整 JSON）
│  │  │  ├─client.jar
│  │  │  └─natives\{java,jna,lwjgl,netty}\
│  │  └─...
│  ├─objects\<sha1[:2]>\<sha1>          ← 【v2.1】唯一物理副本，只读
│  └─cache\
│     ├─version_manifest_v2.json         ← Mojang 版本列表缓存
│     └─icons\<sha1>.<ext>               ← 整合包封面、头像
├─configs\
│  ├─launcher.json                       ← 启动器设置（原 settings.json）
│  ├─accounts.json                       ← 账号（原 auth.json）
│  └─synced\                             ← 【v2.2】同步组的规范数据
├─instances\
│  └─<folder>\
│     ├─instance.json
│     ├─manifest.json
│     ├─mods\ config\ saves\ logs\ resourcepacks\ shaderpacks\ crash-reports\
│     └─missing-files.txt                ← 可选，CurseForge 解析失败时生成
├─logs\
│  └─launcher\launcher-YYYYMMDD.log      ← 仅启动器自身日志
├─templates\
│  └─<template_id>\
│     ├─template.json
│     └─config\ resourcepacks\ ...       ← 只放模板内容，不放游戏本体
└─.trash\<folder>-<yyyyMMdd-HHmmss>[-n]\
```

## 2. 各目录职责

| 目录 | 写者 | 说明 |
|---|---|---|
| `shared/assets` `shared/libraries` `shared/versions` | 安装器 | 所有实例共用，按 Minecraft 标准布局，不要自创结构 |
| `shared/objects` | 文件存储 | v2.1 内容寻址库；只读 |
| `shared/cache` | 启动器 | 可随时删除，删掉只影响速度不影响正确性 |
| `configs` | 启动器 | 用户可见的设置与账号 |
| `instances/<folder>` | 启动器 / 游戏 | 游戏的工作目录，必须自包含 |
| `logs/launcher` | 启动器 | 只放启动器日志；游戏日志在实例内的 `logs/` |
| `templates` | 启动器 / 用户 | 新建实例时的默认内容 |
| `.trash` | 启动器 | 删除实例时先移到这里，可手工还原 |

## 3. 明确不放的东西

- **不放 `shared/mods`、`shared/resourcepacks`、`shared/shaderpacks`**。Minecraft 没有"从全局目录读 mod"的机制，共享目录只会让不同版本/加载器的实例互相污染。需要省空间走 v2.1 的对象库 + 硬链接。
- **不放 `logs/minecraft`**。游戏日志写在当前工作目录（必须=实例目录）的 `logs/` 下，集中只能靠链接，而日志会被原地重写和轮转，链接会出事。界面直接读 `instances/<folder>/logs/latest.log`。
- **`shared/versions/version_manifest_v2.json` 不再放这里**，改到 `shared/cache/`，保证"versions 下全是版本目录"这个不变量成立。

## 4. 实例目录命名

设置项 `instance_id_style`，取值 `slug`（默认）或 `opaque`。

| 模式 | 规则 | 示例 |
|---|---|---|
| `slug` | 显示名转 `[a-z0-9-]`；结果为空或全是非 ASCII 时回退 `inst-<6 位 hex>` | `create-mechanic` / `inst-3f2a1b` |
| `opaque` | 直接 `inst-<8 位 hex>` | `inst-9c4e77a1` |

约束：

- **显示名只存在 `instance.json` 里**，目录名创建后不随显示名改动。
- 重名：`slug` 冲突加 `-2`、`-3`；`opaque` 冲突重新生成。
- 目录名长度上限 48 字符。超过 `MAX_PATH` 风险的场景优先用 `opaque`。

## 5. 根目录与路径

- `A2CR_ROOT` 环境变量整体覆盖根目录，沿用这个名字（测试、便携、截图演示都用它）。
- 所有路径只能从 `LauncherPaths` 一个类取，禁止在业务代码里拼 `Environment.GetFolderPath`。
- 所有拼接出来的路径在进入文件操作前要处理长路径：统一用 `\\?\` 前缀（或 .NET 默认的长路径支持），避免中文实例名 + maven 深层目录撞 260 字符。
- 根目录若位于 OneDrive 同步范围，v2.1 启用对象库时要警告（同步客户端会破坏硬链接）。

## 6. 首次启动

必须创建全部目录，**幂等**。

- 创建失败不能让窗口起不来：显示兜底页，给出"哪个目录、什么错误"的可操作提示（这是 v1 issue #4 的教训）。
- 缺目录时不吞异常，但要在 UI 层转成人类可读文案。

## 7. 不变量

1. `instances/*` 只允许一层目录，任何 `../` 逃逸都要拒绝。
2. `.trash` 里的目录名必须能还原出原实例名（`<folder>-<时间戳>`）。
3. `shared/cache` 被整个删除后，启动器仍能正常工作（只是变慢）。
4. 实例目录内的 `logs/`、`crash-reports/` 不参与任何去重和同步。
