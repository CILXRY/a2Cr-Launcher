# 错误与日志

## 1. 异常分类

```csharp
LauncherException                  // 基类：Code + Message（中文，可直接展示）+ Hint + InnerException
├─ UsageException                  // 参数 / 用法错误
├─ DownloadException               // 下载失败（带失败明细）
├─ AuthException                   // 登录 / 续期失败
├─ LaunchException                 // 启动失败
│  ├─ MissingFilesException        // classpath 缺文件
│  └─ JavaNotFoundException        // 找不到合适的 Java
├─ PackException                   // 整合包
│  ├─ UnsupportedPackException     // 认不出格式
│  └─ PackResolveException         // 清单解析不出来 / 文件查不到
├─ InstanceException               // 元数据损坏、目录越界
├─ SettingsException               // 设置文件损坏到无法回退
└─ StorageException                // 硬链接失败、GC 越界、只读盘
```

规则：

- 每个异常都带一个**稳定的 `Code`**（见第 2 节）和一句**中文 `Message`**；
  `Message` 要能直接进弹窗，技术细节放 `InnerException` 或日志。
- 不允许 `throw new Exception("…")`，也不允许只写英文。
- **不允许把 `OperationCanceledException` 包进上面任何一类。**

## 2. 错误码

`--json` 的 `error.code` 用这张表里的值，**发布后不改**（脚本会依赖）：

| Code | 含义 |
|---|---|
| `usage` | 参数错误 / 缺少必填 |
| `needs_confirmation` | 需要确认但没给 `--yes`（退出码 2） |
| `cancelled` | 用户取消（退出码 3） |
| `download_failed` | 下载失败（含明细） |
| `mirror_unavailable` | 镜像不可用（可切换或重试） |
| `auth_failed` | 登录失败 |
| `auth_expired` | 令牌失效，需要重新登录 |
| `java_missing` | 没有满足要求的 Java |
| `java_invalid` | 指定路径不是可用的 Java |
| `version_unknown` | 版本 id 不存在 |
| `meta_incomplete` | 版本元数据不完整（缺 arguments 等） |
| `missing_files` | classpath 缺文件 |
| `pack_unsupported` | 整合包格式不支持 |
| `pack_resolve_failed` | 整合包文件解析失败 |
| `instance_broken` | 实例元数据损坏 |
| `instance_missing` | 实例不存在 |
| `storage_failed` | 写盘 / 硬链接 / GC 失败 |
| `internal` | 兜底，未分类的错误 |

新增 code 只追加，不复用旧值。

## 3. 取消与退出码

| 情形 | 表达 | 退出码 |
|---|---|---|
| 成功（含"全部跳过"） | 正常返回 | 0 |
| 用户取消（Ctrl+C、点取消） | `OperationCanceledException` | 3 |
| 参数 / 用法错误，或需要确认却没给 `--yes` | `UsageException` | 2 |
| 其他一切失败 | `LauncherException` 及其子类 | 1 |

UI 侧必须这样捕获，**顺序不能错**：

```csharp
catch (OperationCanceledException) when (ct.IsCancellationRequested) { /* 取消，不报错 */ }
catch (LauncherException ex) { /* 展示 Message + Hint */ }
```

先接 `OperationCanceledException`：顺序错了，用户点取消会看到"下载失败"的红色弹窗。
取消时已经写好的 `.part` 必须保留（见 [`05-下载与进度.md`](05-下载与进度.md) 第 6 节）。

## 4. 日志

### 4.1 位置

| 日志 | 路径 | 谁写 |
|---|---|---|
| 启动器 | `logs/launcher/launcher-YYYYMMDD.log` | 启动器 |
| 游戏 | `instances/<folder>/logs/latest.log` | 游戏自己写，启动器只读 |
| 崩溃报告 | `instances/<folder>/crash-reports/` | 游戏自己写 |

**游戏日志不收集、不复制、不做链接**（见 [`02-目录结构.md`](02-目录结构.md) 第 6 节）。

### 4.2 格式与轮转

```text
2026-11-21 23:40:12.345 [INFO ] [download] 完成 300/1000 个文件
2026-11-21 23:40:13.001 [ERROR] [launch] java_missing: 没有找到 Java 21
```

- 时间用本地时间到毫秒；级别用 `DEBUG / INFO / WARN / ERROR`，保留天数由
  `advanced.log_keep_days` 决定（默认 7）。
- 单文件超过 10 MB 就滚动到 `.1`，避免一个坏循环把盘写满。
- 正常流程用 `INFO`；可恢复的问题用 `WARN`；用户操作失败用 `ERROR`。
- 日志写入失败（只读盘、被占用）**不能影响主流程**：捕获后静默降级。

### 4.3 脱敏

必须替换成 `***`：

- `access_token`、`refresh_token`、`Authorization` 头；
- `curseforge_key`；
- 游戏命令行里的 `--accessToken`、`--uuid` 等参数值。

写日志时统一走一个 `Redact()` 入口，不要指望每个调用点都记得。

## 5. 分层约束

**Core 里不许 `Console.Write*`，也不许直接写日志文件。**

- Core 只抛异常，或者通过注入的 `ILogger` 接口输出；
- CLI 把日志写到 stderr / 文件；
- GUI 写进日志页并落盘。

这条要写进 `AGENTS.md`，并在 CI 里 grep `a2Cr.Core` 项目的 `Console.Write`。
v1 的 `core/download.py` 里直接 `print`（连自己定的规矩都破了），v2 不要再犯。

## 6. 面向用户的文案

| 场景 | 要求 |
|---|---|
| 网络失败 | 说"检查网络或代理"，并说明"已下载的文件会保留，重新执行可继续" |
| 镜像不可用 | 说可以换官方源或关掉，不要只说"请求失败" |
| 找不到 Java | 说需要哪个主版本，并给"在设置里指定"的入口 |
| 指定 Java 失效 | 说清是哪个路径失效，**不要悄悄换成自动发现的版本** |
| classpath 缺文件 | 说缺几个、是哪个版本，给"重新安装" |
| 整合包格式不支持 | 列出支持的三类格式 |
| 账号过期 | 说"已降级为离线启动"，给"重新登录" |
| 实例元数据损坏 | 指明是哪个文件，说明已按空实例处理、不会覆盖原文件 |

禁止：只显示异常类名、只显示英文、只显示 `NullReferenceException`、只显示"未知错误"。

## 7. 崩溃兜底

- 全局未处理异常：写日志 → 显示可复制的错误摘要（含 `Code` 和日志路径）→ 提供"打开日志目录"。
- 不弹 Windows 原始崩溃框。
- **启动阶段**（窗口还没起来）的异常：退回控制台输出 + 退出码 1，保证 CI 和脚本能拿到结果。
- 反复崩溃时提示"用 `doctor` 自检"，不要只让用户重装。

## 8. 验收

- 每个异常在 CLI 和 GUI 里都能显示出 `Message`，不出现堆栈。
- 取消：退出码 3，`.part` 保留，重新执行能续上。
- 日志里搜不到 `access_token` / `refresh_token` / `curseforge_key` 的真实值。
- 日志目录设成只读时，主流程仍然能跑（只是没有日志）。
- 杀掉进程模拟崩溃 → 下次启动能看到"上次异常退出"的提示，而不是静默。
