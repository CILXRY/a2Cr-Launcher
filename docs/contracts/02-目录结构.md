## 1. 分层的判据

目录怎么分，只有一个判据：**删了之后能不能再长出来。**

| 层 | 能不能重建 | 谁来写 | 结论 |
|---|---|---|---|
| `cache` | 能（重新下载即可） | 启动器 | 随便删，删了只是变慢 |
| `pool` | **不能**（用户导入的东西） | 用户 + 启动器 | 必须有备份价值，不能被"清理"误删 |
| `instances` | 不能，但它只是**引用 + 私有状态** | 游戏 | 删实例不该动池子 |

命名按"能否重建"来分，不按"是否共享"来分——`cache` 和 `pool` 都叫"共享"，
按共享命名会在文档里互相串。

### 已经定下来的六条

1. **池内文件创建后不再修改**，更新 = 新增文件 + 对账 + GC 旧文件。
2. **硬链接只用于只读内容**：mod、资源包、光影。存档和配置永远不链接。
3. **只在启动时对账**，不做运行中热重载。
4. **`options.txt` 用副本 + 提升**：启动时从池里合成一份，退出时按白名单写回。
5. **存档用副本 + 提升**，不链接、不联接；共享与否由"共享组"决定（见 5.4）。
6. **`instances` 里只有引用和私有状态**，真正的数据都在池子里。

## 2. 完整布局

```text
%USERPROFILE%\.a2CrLauncher\                 ← A2CR_ROOT 可整体覆盖
├─cache\                                     ← 可重建，随便删
│  ├─assets\
│  │  ├─indexes\<index_id>.json
│  │  └─objects\<hash[:2]>\<hash>
│  ├─libraries\<group path>\<artifact>-<ver>[-<classifier>].jar
│  ├─log_configs\<id>
│  ├─versions\<version_id>\
│  │  ├─<version_id>.json                    ← 完整版本元数据
│  │  ├─client.jar
│  │  └─natives\
│  └─meta\
│     ├─version_manifest_v2.json             ← Mojang 列表缓存
│     └─icons\<sha1>.<ext>                   ← 封面、头像缓存
├─pool\                                      ← 用户内容，只增不改
│  ├─mods\<name>-<version>.jar
│  ├─resourcepacks\
│  ├─shaderpacks\
│  ├─options\
│  │  ├─base.txt                             ← 版本无关的键
│  │  └─<mc_version>.txt                     ← 版本相关的覆盖
│  └─saves\<world>\                          ← 世界库；存档池默认关闭
├─instances\<folder>\
│  ├─instance.json                           ← 元信息（03）
│  ├─manifest.json                           ← 文件归属（03）
│  ├─mods\  resourcepacks\  shaderpacks\     ← 硬链接到 pool
│  ├─config\  options.txt  servers.dat\      ← 实例私有，复制不链接
│  ├─saves\                                  ← 见第 5.4 节
│  ├─logs\  crash-reports\                   ← 实例私有，不参与共享
│  └─missing-files.txt                       ← 可选，CurseForge 解析失败时
├─configs\
│  ├─launcher.json                           ← 启动器设置（原 settings.json）
│  └─accounts.json                           ← 账号
├─templates\<template_id>\
│  ├─template.json
│  └─config\ resourcepacks\ ...              ← 只放模板内容，不放游戏本体
├─logs\launcher\launcher-YYYYMMDD.log        ← 只有启动器自己的日志
└─.trash\<folder>-<yyyyMMdd-HHmmss>[-n]\
```

## 3. 各目录职责

| 目录 | 写者 | 说明 |
|---|---|---|
| `cache/assets` `cache/libraries` `cache/versions` | 安装器 | 所有实例共用，按 Minecraft 标准布局，不要自创结构 |
| `cache/meta` | 启动器 | 缓存类数据，删掉只影响速度 |
| `pool/mods` `pool/resourcepacks` `pool/shaderpacks` | 用户 / 导入器 | **游戏永远不直接读这里**，由启动器物化到实例 |
| `pool/options` | 启动器 | 配置声明，不是完整文件（见第 5.5 节） |
| `pool/saves` | 游戏（经实例） | 按 MC 版本分桶，见第 5.4 节 |
| `instances/<folder>` | 启动器 / 游戏 | 游戏的工作目录，游戏只认这里 |
| `configs` | 启动器 | 用户可见的设置与账号 |
| `logs/launcher` | 启动器 | 游戏日志不在这里（见第 6 节） |
| `templates` | 启动器 / 用户 | 新建实例时的默认内容 |
| `.trash` | 启动器 | 删除实例时先移到这里，可手工还原 |

## 4. 实例目录命名

设置项 `instance_id_style`，取值 `slug`（默认）或 `opaque`。

| 模式 | 规则 | 示例 |
|---|---|---|
| `slug` | 显示名转 `[a-z0-9-]`；结果为空或全是非 ASCII 时回退 `inst-<6 位 hex>` | `create-mechanic` / `inst-3f2a1b` |
| `opaque` | 直接 `inst-<8 位 hex>` | `inst-9c4e77a1` |

约束：

- **显示名只存在 `instance.json` 里**，目录名创建后不随显示名改动。
- 重名：`slug` 冲突加 `-2`、`-3`；`opaque` 冲突重新生成。
- 目录名长度上限 48 字符。超过 `MAX_PATH` 风险的场景优先用 `opaque`。

## 5. 池子怎么共享到实例

这是整个设计的核心：**池子是唯一副本，实例里是硬链接。**

### 5.1 为什么不用目录联接（junction）

目录联接能让多个实例"看见"同一个文件夹，但会带来三个问题：

1. 实例目录不再自包含，备份、移动、删除都会变得难以预测；
2. 无法按实例覆盖——想给某个实例加一个只它自己有的包，做不到；
3. 某些工具会递归穿越联接，产生"删了 A 结果 B 也没了"的效果。

所以：**实例里放真目录，文件用硬链接指向池子。** 目录是实例的，数据是共享的。

### 5.2 启动时的对账（reconcile）

每次启动前，对 `mods` / `resourcepacks` / `shaderpacks` 三个目录做一次对账：

```text
对池子里的每个文件：
    实例里没有同名文件            → 建硬链接
    实例里已有同名文件且是链接     → 检查目标是否同一个，不是则重建
    实例里已有同名文件但不是链接   → 用户自己的文件，跳过，记为 origin=user

对实例里的每个链接：
    池子里已经没有这个文件        → 删除链接（GC）
```

对账是**幂等**的，跑一百次和跑一次结果一样。它带来两个效果：

- 在 A 实例里加了包，B 实例**下次启动**就能看到——满足"持续共享"；
- 池子里删掉的 mod，下次启动时从实例里消失，不会留下悬空链接。

对账只在**启动时**做，不做运行中监听——游戏加 mod / 资源包本来就要重开，
监听池子只会增加不一致的窗口（决策 33）。

### 5.3 单文件用硬链接，不用复制

- 硬链接不占额外空间，程序看到的仍是普通文件，Forge / Iris 扫描都没问题；
- **同一分区**是前提。池子和实例都在同一个根目录下，正常不会跨盘；跨盘时退化为复制并报告；
- 硬链接的前提是"池内文件永不被原地改写"（见第 9 节不变量）。

### 5.4 存档：共享组 + 副本提升

存档格式随版本变化（新版会**升级**存档，升级后旧版再也打不开），而且不同 mod 集合
写出来的世界数据不兼容。所以能不能共享，由**共享组**决定：

- 同一个原版版本的原版实例 → 同一组；
- 从同一个 mod 基础克隆出来的实例 → 同一组（组 id 在克隆时写进实例元数据）；
- 其他情况 → **不进池，独占**。

**存档池默认关闭。** 关闭时一切按独占走：实例里的 `saves/` 就是真目录，游戏随便写，
行为和普通启动器完全一样。开启时才走下面这套。

#### 为什么不能链接

存档不能硬链接、也不能用目录联接。Minecraft 写 region 文件是**原地随机写**，
`level.dat` 反复重写，还有 `session.lock`——共享同一个物理文件，任何一次写入都会
同时改掉两边，而且不会报错。这是整个设计里唯一"必须复制"的地方。

#### 生命周期

```text
启动前：  池 ──复制──> 实例（池那份保持不动）
游戏中：  游戏只写实例里这份
退出后扫描：
  ├─ 有改动    → 提升回池：实例这份成为池里的新版本，旧版本压缩归档保留一份
  ├─ 被删掉了  → 解除这个实例的引用；还有别的实例引用 → 世界仍在；没人引用 → 进回收站
  └─ 没改动    → 丢弃实例这份，引用不变
```

判断"有没有改动"用 `level.dat` 和 region 文件的 mtime/size 快扫。**拿不准就当成改过**，
宁可多复制一次，也不能误丢进度。

#### 成本控制

- 复制发生在**分配时**和**有改动时**，不是每次启动都全量复制；
- 旧版本用 zstd 压缩归档（体积约一半，速度比裸复制快）；
- 超过阈值（按磁盘实测写速算，不是写死大小）自动降级为"**只保留上一次会话**"，
  UI 要说明代价是可能丢一次进度；
- 崩溃没有"退出后扫描"，下次启动要能发现残留副本并询问。

#### 世界身份与并发

- 每个世界目录里有 **`al-saves.uuid`**，写着这个世界的稳定 id。改名、移动都不影响识别，
  不需要靠文件夹名猜。
- 实例侧的 `manifest.json` 里记录"这个实例引用了哪个 save uuid"（见 `03-实例与清单.md`）。
- 两个实例打开同一个世界时**必须提示**，不做静默放行。
  `【待确认】` 提示的形式（启动前弹窗 / 只警告不拦 / 强制只读打开）还没定。

### 5.5 配置：池里存声明，不存文件

`options.txt` 是游戏拥有、退出时整份重写的文件。池子里存一份完整文件等于和游戏抢所有权，
所以池里存的是**键值声明**：

```text
pool\options\base.txt          ← 版本无关的键：画面、声音、FOV、按键
pool\options\<mc_version>.txt  ← 版本相关的覆盖
```

启动时按 `base → 版本 → 实例` 顺序合成这个实例的 `options.txt`。

必须遵守的三条（细节在 `产品想法.md`）：

1. 用**白名单**决定哪些键能共享，不要用"两个文件都有的键"当交集；
2. `soundDevice`（机器相关）、`fullscreen`、`lastServer` 以及任何 mod 写入的键，不由这个池管理；
3. v2.0 只做**单向注入**（启动时写进实例），不做退出回写。回写要判断"这次真的改过没有"，放 v2.2。

**资源包列表由这个池管理，默认共享，实例可覆盖**（`resourcepack_list: shared | local`）。
切版本时 `pack_format` 不兼容会让游戏把包挪进"已禁用"，所以池里保存一份授权列表，
下次启动按它恢复——这正好解决"得一个一个加回去"的问题。

## 6. 明确不放的东西

- **不放"让游戏直接读的全局 mod 目录"。** Minecraft 没有这个机制，直接把 `pool/mods` 指给游戏
  会让不同版本 / 加载器的实例互相污染。池子只被启动器读，由启动器物化到实例。
- **不放 `logs/minecraft`。** 游戏日志写在进程工作目录（= 实例目录）的 `logs/` 下；集中只能靠链接，
  而日志会被原地重写和轮转，链接一定出事。界面直接读 `instances/<folder>/logs/latest.log`。
- **`version_manifest_v2.json` 不放 `cache/versions/`。** 保证"versions 下全是版本目录"这个不变量成立，
  缓存放到 `cache/meta/`。

## 7. 根目录与路径

- `A2CR_ROOT` 环境变量整体覆盖根目录，沿用这个名字（测试、便携、截图演示都用它）。
- 所有路径只能从 `LauncherPaths` 一个类取，禁止在业务代码里拼 `Environment.GetFolderPath`。
- 拼接出来的路径在进入文件操作前要处理长路径（`\\?\` 前缀或 .NET 的长路径支持），
  避免中文实例名 + maven 深层目录撞 260 字符。
- 根目录若位于 OneDrive 等同步范围，启用池子 / 硬链接时要警告：同步客户端会破坏链接。

## 8. 首次启动

必须创建全部目录，**幂等**。

- 创建失败不能让窗口起不来：显示兜底页，给出"哪个目录、什么错误"的可操作提示（v1 issue #4 的教训）。
- 缺目录时不吞异常，但要在 UI 层转成人类可读文案。

## 9. 不变量

1. `instances/*` 只允许一层目录，任何 `../` 逃逸都要拒绝。
2. `.trash` 里的目录名必须能还原出原实例名（`<folder>-<时间戳>`）。
3. `cache` 被整个删除后，启动器仍能正常工作（只是变慢）。
4. **`pool` 里的文件一旦创建就不再修改**：更新 = 新增文件 + 重新对账 + GC 旧文件。
5. **`pool` 里没有任何实例引用的文件，才能被 GC。** 判断依据是实例清单，不是文件系统里的链接数
   （链接数会被备份工具、资源管理器操作影响）。
6. 实例里"不是链接、也不在清单里"的文件属于用户，**永不自动删除**。
7. 删除实例只做"移进 `.trash` + 断开链接"，绝不动 `pool` 里的内容。
8. 实例内的 `logs/`、`crash-reports/` 不参与任何共享、去重和同步。
9. **存档、`options.txt`、`config/` 不用硬链接，也不用目录联接**，只用副本 + 提升。
   游戏会原地重写这些文件，链接一定会互相污染。
