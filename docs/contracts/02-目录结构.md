# 目录结构

## 分层

根据 **可重建性** 来区分目录所属。

| 层          | 能不能重建                        | 谁来写        | 结论                               |
|-------------|-----------------------------------|---------------|------------------------------------|
| `shared`    | 可重新下载                        | 启动器        | 类似于传统启动器的 `.minecraft`    |
| `pool`      | **不能**（用户导入的东西）        | 用户 + 启动器 | 共享池，将可共享的内容放到这里     |
| `instances` | 不能，但它只是**引用 + 私有状态** | 游戏          | 各个实例目录 `.minecraft/versions` |

## 完整布局

```text
%USERPROFILE%\.a2CrLauncher\                 ← A2CR_ROOT 可整体覆盖
├─shared\                                    ← 可重建
│  ├─assets\
│  │  ├─indexes\<index_id>.json
│  │  └─objects\<hash[:2]>\<hash>
│  ├─libraries\<group path>\<artifact>-<ver>[-<classifier>].jar
│  ├─log_configs\<id>
│  ├─versions\<version_id>\
│  │  ├─<version_id>.json                    ← 完整版本元数据
│  │  ├─<version_id>-assets.json             ← 完整版本 assets 数据
│  │  ├─client.jar
│  │  └─natives\
│  └─meta\
│     ├─version_manifest_v2.json             ← Mojang 列表缓存
│     └─icons\<sha1>.<ext>                   ← 封面、头像缓存
├─pool\                                      ← 用户内容，只增不改
│  ├─mods\modloader\mc_version\<name>-<version>.jar
│  ├─resourcepacks\
│  ├─shaderpacks\
│  ├─options\
│  │  ├─base.txt                             ← 版本无关的键
│  │  └─<mc_version>.txt                     ← 版本相关的覆盖
│  └─saves\<world>\                          ← 世界库；存档池默认关闭
├─instances\<folder>\
│  ├─instance.json                           ← 元信息（03）
│  ├─manifest.json                           ← 文件归属（03）
│  ├─mods\  resourcepacks\  shaderpacks\     ← 硬链接到 pool
│  ├─config\  options.txt  servers.dat\      ← 实例私有，复制不链接
│  ├─saves\                                  ← 见第 5.4 节
│  ├─logs\  crash-reports\                   ← 实例私有，不参与共享
│  └─missing-files.txt                       ← 可选，CurseForge 解析失败时
├─configs\
│  ├─launcher.json                           ← 启动器设置
│  └─accounts.json                           ← 账号
├─templates\<template_id>\
│  ├─template.json
│  └─config\ resourcepacks\ ...              ← 只放模板内容，不放游戏本体
├─logs\launcher\launcher-YYYYMMDD.log        ← 只有启动器自己的日志
└─.trash\<folder>-<yyyyMMdd-HHmmss>[-n]\
```

## 说明

### 1. 实例目录命名

设置项 `instance_id_style`，取值 `slug`（默认）或 `opaque`。

| 模式     | 规则                                                                  | 示例                              |
|----------|-----------------------------------------------------------------------|-----------------------------------|
| `slug`   | 显示名转 `[a-z0-9-]`；结果为空或全是非 ASCII 时回退 `inst-<6 位 hex>` | `create-mechanic` / `inst-3f2a1b` |
| `opaque` | 直接 `inst-<8 位 hex>`                                                | `inst-9c4e77a1`                   |
| `origin` | 沿用对应的原命名（不推荐）                                            | `机械动力` / `minecraft-26.2`     |

约束：

- **显示名只存在 `instance.json` 里**，目录名创建后不随显示名改动。
- 重名：`slug` 冲突加 `-2`、`-3`；`opaque` 冲突重新生成。
- 目录名长度上限 48 字符。超过 `MAX_PATH` 风险的场景优先用 `opaque`。
- （如果可以）避免中文实例名 + maven 深层目录撞 260 字符。

### 已经定下来的六条

1. **池内文件创建后不再修改**，更新 = 新增文件 + 对账 + GC 旧文件。
2. **硬链接只用于只读内容**：mod、资源包、光影。存档和配置永远不链接。
4. **`instances` 里只有引用和私有状态**，真正的数据都在池子里。

### 2. 共享资源池

资源池内容唯一、文件硬链接到实例

回退采用：硬链接 > 复制

- 硬链接不占额外空间，程序看到的仍是普通文件。
- **同一分区**是前提。资源池和实例都在同一个根目录下，正常不会跨盘；跨盘时退化为复制并报告。
- 硬链接的前提是"池内文件永不被原地改写"（见第 6 节不变量）。

#### 2.1 任何情况下都不考虑使用软链接 / 目录联接

最简单的讲就是这是共享资源池而不是独享。

1. 实例目录不再自包含，备份、移动、删除都会变得难以预测；
2. 无法按实例覆盖——想给某个实例加一个只它自己有的包，做不到；
3. 某些工具会递归穿越联接，产生"删了 A 结果 B 也没了"的效果。

#### 2.2 资源池检查

每次启动启动器后，对 `mods` / `resourcepacks` / `shaderpacks` 三个目录做一次资源池检查：

```text
对资源池里的每个文件：
    实例里没有同名文件             → 建硬链接
    实例里已有同名文件且是链接     → 检查目标是否同一个，不是则重建
    实例里已有同名文件但不是链接   → 用户自己的文件，跳过，记为 origin=user

对实例里的每个链接：
    资源池里已经没有这个文件       → 删除链接（GC）
```

资源池检查是 **幂等** 的，它带来两个效果：

- 在 A 实例里加了包，B 实例 **下次启动**就能看到——满足"持续共享"；
- 资源池里删掉的 mod，下次资源池检查时从实例里消失，不会留下悬空链接。

#### 2.3 存档

**存档用副本 + 提升**，不链接、不联接；共享与否由"共享组"决定。

存档格式随版本变化（新版会 **升级**存档，升级后旧版再也打不开），而且不同 mod 集合 写出来的世界数据不兼容。所以能不能共享，由
**共享组**决定：

- 同一个原版版本的原版实例 → 同一组；
- 从同一个 mod 基础克隆出来的实例 → 同一组（组 id 在克隆时写进实例元数据）；
- 其他情况 → **不进池，独占**。

**存档池默认关闭。** 关闭时一切按独占走：实例里的 `saves/` 就是真目录，游戏随便写， 行为和普通启动器完全一样。开启时才走下面这套。

##### 为什么不能链接

存档不能硬链接、也不能用目录联接。Minecraft 写 region 文件是 **原地随机写**，
`level.dat` 反复重写，还有 `session.lock`——共享同一个物理文件，任何一次写入都会
同时改掉两边，而且不会报错。这是整个设计里唯一"必须复制"的地方。

##### 生命周期

```text
启动前：  池 ──复制──> 实例（池那份保持不动）
游戏中：  游戏只写实例里这份
退出后扫描：
  ├─ 有改动    → 提升回池：实例这份成为池里的新版本，旧版本压缩归档保留一份
  ├─ 被删掉了  → 解除这个实例的引用；还有别的实例引用 → 世界仍在；没人引用 → 进回收站
  └─ 没改动    → 丢弃实例这份，引用不变
```

判断"有没有改动"用 `level.dat` 和 region 文件的 mtime/size 快扫。 **拿不准就当成改过**， 宁可多复制一次，也不能误丢进度。

##### 成本控制

- 复制发生在 **分配时**和 **有改动时**，不是每次启动都全量复制；
- 旧版本用 zstd 压缩归档（体积约一半，速度比裸复制快）；
- 超过阈值（按磁盘实测写速算，不是写死大小）自动降级为"**只保留上一次会话**"， UI 要说明代价是可能丢一次进度；
- 崩溃没有"退出后扫描"，下次启动要能发现残留副本并询问。

##### 世界身份与并发

- 每个世界目录里有 **`al-saves.uuid`**，写着这个世界的稳定 id。改名、移动都不影响识别， 不需要靠文件夹名猜。
- 实例侧的 `manifest.json` 里记录"这个实例引用了哪个 save uuid"（见 `03-实例与清单.md`）。
- 两个实例打开同一个世界时 **必须提示**，不做静默放行。
  `【待确认】` 提示的形式（启动前弹窗 / 只警告不拦 / 强制只读打开）还没定。

#### 2.4 `options.txt`

配置：池里存声明，不存文件 **`options.txt` 用副本 + 提升**：启动时从资源池里合成一份，退出时按白名单写回。

`options.txt` 是游戏拥有、退出时整份重写的文件。资源池里存一份完整文件等于和游戏抢所有权， 所以池里存的是 **键值声明**：

```text
pool\options\base.txt          ← 版本无关的键：画面、声音、FOV、按键
pool\options\<mc_version>.txt  ← 版本相关的覆盖
instances\*\options.txt        ← 对应实例自己的覆盖
```

启动时按 `base → 版本 → 实例` 顺序合成这个实例的 `options.txt`。

必须遵守的三条（细节在 `产品想法.md`）：

1. 用 **白名单**决定哪些键能共享，不要用"两个文件都有的键"当交集；
2. `soundDevice`（机器相关）、`fullscreen`、`lastServer` 以及任何 mod 写入的键，不由这个池管理；
3. v2.0 只做 **单向注入**（启动时写进实例），不做退出回写。回写要判断"这次真的改过没有"，放 v2.2。

**资源包列表由这个池管理，默认共享，实例可覆盖**（`resourcepack_list: shared | local`）。 切版本时 `pack_format`
不兼容会让游戏把包挪进"已禁用"，所以池里保存一份授权列表， 下次启动按它恢复——这正好解决"得一个一个加回去"的问题。

### 3. 明确不放的东西

- **不放"让游戏直接读的全局 mod 目录"。** Minecraft 没有这个机制，直接把 `pool/mods` 指给游戏 会让不同版本 /
  加载器的实例互相污染。池子只被启动器读，由启动器物化到实例。
- **不放 `logs/minecraft`。** 游戏日志写在进程工作目录（= 实例目录）的 `logs/` 下；集中只能靠链接， 而日志会被原地重写和轮转，链接一定出事。界面直接读
  `instances/<folder>/logs/latest.log`。
- **`version_manifest_v2.json` 不放 `shared/versions/`。** 保证"versions 下全是版本目录"这个不变量成立， 缓存放到
  `shared/meta/`。

### 4. 根目录与路径

- `A2CR_ROOT` 环境变量整体覆盖根目录。
- 所有路径只能从 `LauncherPaths.cs` 一个类取，禁止在业务代码里拼 `Environment.GetFolderPath`。
- 拼接出来的路径在进入文件操作前要处理长路径（`\\?\` 前缀或 .NET 的长路径支持）。
- 根目录若位于 OneDrive 等同步范围，启用共享池 / 硬链接时要警告：同步客户端会破坏链接。

### 5. 首次启动

必须创建全部目录， **幂等**。

- 创建失败不能让窗口起不来：显示兜底页，给出"哪个目录、什么错误"的可操作提示（v1 issue #4 的教训）。
- 缺目录时不吞异常，但要在 UI 层转成人类可读文案。

### 6. 不变量

1. `instances/*` 只允许一层目录，任何 `../` 逃逸都要拒绝。
2. `.trash` 里的目录名必须能还原出原实例名（`<folder>-<时间戳>`）。
3. `cache` 被整个删除后，启动器仍能正常工作（只是变慢）。
4. **`pool` 里的文件一旦创建就不再修改**：更新 = 新增文件 + 重新对账 + GC 旧文件。
5. **`pool` 里没有任何实例引用的文件，才能被 GC。** 判断依据是实例清单，不是文件系统里的链接数 （链接数会被备份工具、资源管理器操作影响）。
6. 实例里"不是链接、也不在清单里"的文件属于用户， **永不自动删除**。
7. 删除实例只做"移进 `.trash` + 断开链接"，绝不动 `pool` 里的内容。
8. 实例内的 `logs/`、`crash-reports/` 不参与任何共享、去重和同步。
9. **存档、`options.txt`、`config/` 不用硬链接，也不用目录联接**，只用副本 + 提升。 游戏会原地重写这些文件，链接一定会互相污染。
