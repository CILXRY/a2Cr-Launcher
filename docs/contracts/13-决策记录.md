# 决策记录

一行一个决策，只记**为什么**。改契约前先在这里加一条。

| # | 日期 | 决策 | 理由 / 代价 |
|---|---|---|---|
| 1 | 2026-11 | 技术栈从 Python + Flet 迁到 C# + Avalonia | Flet 打包 132 MB / 1900 文件，包含 33 MB 误打包的开发工具；Avalonia 单文件预期 35–55 MB。更重要的动机是 Flet 的布局 API 和维护成本 |
| 2 | 2026-11 | 核心逻辑全部自研，不引入 CmlLib.Core | 练习项目；要完全控制 Forge/NeoForge 安装细节。代价：最危险的 1.5k 行要自己复刻，必须靠 golden 数据兜底 |
| 3 | 2026-11 | 保留 CLI，用 C# 重写（`System.CommandLine`） | 与 GUI 共用 Core，成本低；脚本用户不受影响 |
| 4 | 2026-11 | 不兼容 v1 数据格式 | 全部重写；只要探测旧目录决定 `defaults_profile`，不读旧文件。代价：老用户升级后需要重新导入整理包（可选做一个 `migrate` 工具） |
| 5 | 2026-11 | 目录分 `shared / configs / instances / logs / templates / .trash` | 把"共享的只读内容"和"每实例可变内容"在物理上分开，便于以后加对象库 |
| 6 | 2026-11 | 不设 `shared/mods`、`shared/resourcepacks`、`shared/shaderpacks` | Minecraft 没有全局 mod 目录机制；共享目录会让不同版本/加载器的实例互相污染 |
| 7 | 2026-11 | 游戏日志不集中到根目录 `logs/` | 日志写在进程工作目录；集中只能靠链接，而日志会被原地重写和轮转，链接会出事。UI 直接读实例内的 `logs/latest.log` |
| 8 | 2026-11 | 实例目录名支持 `slug` / `opaque`，创建后不随显示名改变 | 中文名 + 深层 maven 路径容易撞 260 字符上限；目录名稳定才能让清单路径长期有效 |
| 9 | 2026-11 | 克隆实例用**按文件硬链接**，白名单只包含 `mods` / `resourcepacks` / `shaderpacks` | 目录符号链接需要管理员权限、破坏备份、删除易出事；硬链接瞬时且零额外空间。代价：必须守住"永不原地覆盖"的写入纪律 |
| 10 | 2026-11 | `saves` / `config` / `options.txt` / `servers.dat` 克隆时复制，绝不链接 | 会被原地重写，链接会导致两实例互相污染或存档损坏 |
| 11 | 2026-11 | 引入 `manifest.json` 记录每个文件的 `origin`，取代 v1 的 `managed_files` | 更新、模板重置、清理、去重、同步全都依赖文件归属；v1 的 `managed_files` 只覆盖"下载来的文件"，不够用 |
| 12 | 2026-11 | 对象库（内容寻址 + 硬链接）推迟到 v2.1，但 `IFileStore` 接口和写入纪律 v2.0 就要有 | 先拿到"能用的启动器"，再优化磁盘；但写完要审遍全项目才行，所以接缝必须先留 |
| 13 | 2026-11 | 对象库文件设为只读 | 防止用户在资源管理器里原地覆盖，静默截断共享副本。代价：换 mod 必须走启动器 |
| 14 | 2026-11 | 去重默认：新用户开、老用户关；同步默认关 | 去重无感知（省空间），同步会改变行为（需要用户理解），所以分开 |
| 15 | 2026-11 | 同步层（options 字段合并 / servers / config / mod 集合）推迟到 v2.2 | 复杂度约等于下载器 + 启动核心之和；先做好 v2.0 的存储与导入 |
| 16 | 2026-11 | CurseForge 走 API 镜像，可切换到官方 key 或关闭（原稿写"只做本地导入、搜索后置"，已推翻） | 覆盖率值得这个代价；镜像稳定性一般，所以做成可选并允许关闭 |
| 17 | 2026-11 | token 明文存储，不加 DPAPI | 用户会整体拷贝数据目录；加密后跨机器全部失效 |
| 18 | 2026-11 | 取消用 `OperationCanceledException`，与失败严格区分 | v1 的 `DownloadCancelled` 语义要保留：取消会让界面显示"下载失败"，体验很差 |
| 19 | 2026-11 | 二进制产物目标：单文件 ≤ 60 MB、输出文件数 ≤ 20 | 直接对标 Flet 的 132 MB / 1900 文件；用 CI 断言防止依赖膨胀 |
| 20 | 2026-11 | 迁移期 Python 版只修致命 bug，新功能只进 C# | 避免两套实现长期分叉 |
| 21 | 2026-11 | `pool` 里的文件创建后不再修改；更新 = 新增文件 + 启动时对账 + GC 旧文件 | 从根上杜绝"原地覆盖穿透硬链接"；顺带获得原子更新与回滚。代价：同名文件会短暂存在两份 |
| 22 | 2026-11 | 只对只读内容（mod / 资源包 / 光影）用硬链接，`options.txt` `config` `saves` `logs` 一律不链接 | 这些文件会被游戏原地重写，链接过去就是多个实例互相污染 |
| 23 | 2026-11 | 实例里的 `mods` 等是**真目录**，靠启动时对账建立硬链接；不用目录联接 | 联接会让实例不再自包含、无法按实例覆盖、递归工具容易误删。对账幂等，成本只有一次 stat |
| 24 | 2026-11 | 存档按 `mc_version` 分桶共享，`instances/<folder>/saves` 联接指向对应桶 | 新版会升级存档格式，升级后旧版再也打不开；全局共享会造成不可逆损坏。代价：必须检测并发占用 |
| 25 | 2026-11 | `options.txt` 在池里存**键值声明**，启动时按 `base → 版本 → 实例` 合成；v2.0 只做单向注入 | 游戏退出时整份重写该文件，存完整文件等于抢所有权。回写要白名单 + 变更检测，放 v2.2 |
| 26 | 2026-11 | 资源包列表默认共享，实例可覆盖（原稿曾主张不共享，已推翻） | 解决"换版本要重新启用"的痛点；覆盖开关给特殊情况留出口 |
| 27 | 2026-11 | 存档池**默认关闭**，独占是默认路径 | 绝大多数场景不需要跨实例共享存档；默认关闭不会让新用户困惑 |
| 28 | 2026-11 | 共享组 = 同版本原版，或从同一 mod 基础克隆的实例；组 id 在克隆时写入元数据 | 判断不依赖比较 mod 列表，加了 mod 仍是同组；跨组的世界数据不兼容 |
| 29 | 2026-11 | 存档**不硬链接、不目录联接**，只用"副本 + 提升" | MC 原地随机写 region / `level.dat` / `session.lock`，共享物理文件必然互相污染 |
| 30 | 2026-11 | 组内只保留上一次会话，旧版本用 zstd 压缩归档；超过阈值自动降级 | 压缩归档比裸复制快且省一半空间；降级要在 UI 说明"可能丢一次进度" |
| 31 | 2026-11 | 改动判定用 `mtime`/`size` 快扫，拿不准就算改过 | 误判"没改过"会丢进度，误判"改过"只多复制一次，代价不对称 |
| 32 | 2026-11 | 存档池是**可选项**，不做进 v2.0 | 独占模式不需要复制、提升、退出扫描和压缩归档，v2.0 因此小了一大块 |
| 33 | 2026-11 | 不做运行中热重载，一切改动下次启动生效 | MC 加 mod / 资源包本来就要重开游戏；省掉文件监听和运行中一致性 |
| 34 | 2026-11 | 按 M1–M5 五个里程碑推进，每个里程碑打 tag | "能做就做"不能当验收标准；有 tag 才不会出现"半新半旧说不清" |
| 35 | 2026-11 | M1 用 CLI 验收，不要求 GUI | CLI 写得快、能当回归测试、报错清楚；GUI 放 M1 之后 |
| 36 | 2026-11 | Forge / NeoForge 放到 M3，排在 Fabric 之后 | 调官方安装器 + 版本差异，是最容易卡住的地方；放后面卡住不影响交付 |
| 37 | 2026-11 | 镜像和官方 API 的请求都带 `a2cr-launcher/<ver>` UA，不冒充其他启动器 | 镜像站靠 UA 识别调用方；冒充是拿别人的信誉换速度，最容易被拉黑 |
| 38 | 2026-11 | 删除 `r.jina.ai` 网页抓取兜底 | 靠正则解析第三方渲染页面，改版即断，还容易被当成爬虫 |
| 39 | 2026-11 | 公开标识（Azure `app_id`）与密钥凭证（CF key）区别对待：前者可硬编码，后者只存用户本地 | OAuth 的 client_id 本来就是公开的、设备码流程没有 secret；API key 泄露会被人花掉配额并导致 key 作废 |
| 40 | 2026-11 | 世界身份用世界目录里的 `al-saves.uuid` 标记文件，实例侧在 `manifest.json` 记录引用的 uuid | 文件夹名会被游戏内重命名打断；标记文件让改名、移动都还能认出来 |
| 41 | 2026-11 | 两个实例打开同一个世界时**必须提示**（形式待定） | 静默放行等于把"互相覆盖"留给用户事后发现 |
| 42 | 2026-11 | 传输层交给 NuGet `Downloader` 库；校验、原子落盘、批量调度、进度聚合仍由封装负责 | 库管分片 / 续传 / 限速；但硬链接纪律要求"先写 `.part` 再 rename"，不能让库直写目标路径 |
| 43 | 2026-11 | 游戏输出统一转 UTF-8 再输出 | 同一份日志在不同机器上两套编码，用户描述和 bug 报告都对不上 |
| 44 | 2026-11 | 启动前默认不校验哈希、只查存在性；实例可开 `verify_on_launch` 做完整校验 | 全量哈希太慢，但要给"文件坏了"的疑难场景留一个可选的严格模式 |

## 待定

| 事项 | 现状 | 需要什么才能定 |
|---|---|---|
| 是否提供 v1 数据导入工具 | 倾向做，成本低 | 确认老用户规模 |
| 自动更新 | 未设计 | 单文件发布确定后再做（差分更新会容易很多） |
| 多语言 | 字段已留（`language`） | v2.0 只做 `zh-CN` |
| 存档桶的粒度 | 暂定按 `mc_version` | 同版本不同加载器能否共享存档，需要实测 |
| 资源包列表是否共享 | 暂不共享 | 要处理 `pack_format` 不兼容时的回退与修复 |
| 池子变化是否运行中即时生效 | 倾向不做（下次启动生效） | 需要评估文件监听的收益与坑 |
