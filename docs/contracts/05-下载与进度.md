## 1. 两个层级

| 层级 | 用途 | 行为 |
|---|---|---|
| `DownloadFile` | 单个文件 | 校验、续传、重试，返回 `Success / Skipped / Failed` |
| `DownloadBatch` | 一批文件 | 并发、去重、多轮补下、早退保护、统一完成回调 |

两者都**不直接输出到控制台**。CLI 通过回调画进度条，GUI 通过 `IProgress<T>` 更新界面。

## 2. 单文件语义（必须照做，不是可调参数）

| 项 | 值 | 原因 |
|---|---|---|
| 重试次数 | 4 | 偶发网络抖动 |
| 退避 | `min(0.5 * 2^n, 4.0s)` + 0–0.3s 随机抖动 | 避免整批同时重试打垮服务器/代理 |
| 分片大小 | 1 MiB | 断点续传粒度 |
| 超时 | 连接 10s / 读取 60s | 读取超时不能太短，慢速大文件会被误判 |
| 请求头 | `Accept-Encoding: identity` | **必须**。否则服务器压缩后字节偏移和本地不一致，续传会错位 |
| User-Agent | `a2cr-launcher/<version> (+repo)` | 标识来源 |

续传规则：

1. `.part` 已存在且**大于**期望大小 → 一定是坏分片，删掉重下。
2. 否则带 `Range: bytes=<已下载>-`。
3. 服务器返回 `416` → 认为已下完，交给哈希校验判断。
4. **只有返回 `206` 才能追加写**；返回 `200` 必须从头覆盖写。
5. `.part` 哈希通过 → 原子 rename 成目标文件。
6. 哈希不通过 → 删除 `.part`，计入一次失败重试。

已有目标文件时：

- 没给哈希 → 视为跳过（无法校验，不重下）。
- 哈希匹配 → 跳过。
- 哈希不匹配 → 删除重下（不能把坏文件当缓存）。

## 3. 批量语义

| 项 | 值 |
|---|---|
| 并发 | 8 |
| 同一目标路径出现多次 | 按路径去重，只下一次 |
| 全部失败后的补下轮数 | 2 |
| 早退阈值 | 一个都没成功且连续失败 ≥ 12 个 → 立即中止（多半是断网/代理挂了），提示检查网络 |

补下轮次之间固定等待 1.5s、3.0s（不要复用单文件退避，否则用户会感觉卡住）。

## 4. 进度回调

```csharp
public readonly record struct DownloadProgress(
    int Done, int Total, string Name, DownloadStatus Status);

public enum DownloadStatus { Success, Skipped, Failed }
```

- `Done` 是**已处理完的文件数**（成功 + 跳过），不是字节数。
- 每完成一个文件回调一次，`Name` 只给文件名，不给完整路径。
- 传了回调就**不要**再输出任何控制台进度。
- 回调可能来自工作线程，UI 层负责切回主线程。

批量接口的返回值：`bool AllSucceeded` + 失败明细 `IReadOnlyList<(string Path, string Reason)>`。
失败原因要能直接展示给用户（例如 "SHA-1 校验失败（得到 x，期望 y）"）。

## 5. 取消

- 统一用 `CancellationToken`，抛 `OperationCanceledException`。
- **取消不是失败**：不许包成 `DownloadException`，否则界面无法区分"用户点了取消"和"下载失败"。
- 取消时已经写好的 `.part` 必须保留，重新执行同样的下载能续上。
- 批量下载取消后，剩下的文件不再启动；已经开始的文件在下一个分片边界退出。
- `OperationCanceledException` 必须在最外层被单独捕获（`when (ct.IsCancellationRequested)`），不能落到通用 `catch (Exception)` 里被转成"下载失败"。

## 6. 失败上报

| 场景 | 处理 |
|---|---|
| 单文件 4 次重试后仍失败 | 记录原因，批量继续 |
| 批量结束仍有失败 | 返回失败明细，调用方决定是否 `throw` |
| 安装流程中有失败 | 抛 `DownloadException`，提示"重新执行可继续补下"（已下载的会跳过） |
| 版本列表/元数据网络失败 | 回落本地缓存；缓存也没有才报错 |

不要静默失败。v1 的"进度条走完但实际缺文件"是最难排查的体验问题，v2 必须让失败可枚举。

## 7. 不需要的功能

- 分片并行（同一个文件多线程 Range）：收益小，与服务端兼容性风险大，不做。
- 断点续传的 ETag/Last-Modified 校验：Mojang 的 CDN 用哈希就够，不做。
- 代理设置：v2.0 只读系统代理，不做应用内代理配置。

## 8. 测试点

- `.part` 比目标大 → 重下。
- 服务器忽略 Range 返回 200 → 从头写，不追加。
- 服务器返回 416 → 进入哈希校验。
- 取消后 `.part` 保留，下次续传成功。
- 批量里同一路径重复 → 只下载一次。
- 连续失败 12 个 → 中止且给出可读提示。
