# 整合包与内容搜索

> **完善中**：未定稿，`【待确认】` 处需要拍板；和 [`产品想法.md`](../产品想法.md) 冲突时改本文。

搜索页和本地导入是同一件事的两端，共用一套 provider 抽象。**不要为搜索页单独写一套 API 代码**。

## 1. Provider 抽象

```csharp
public interface IModpackProvider
{
    string Id { get; }                       // "modrinth" / "curseforge"
    bool SupportsSearch { get; }

    Task<SearchPage<ModpackSummary>> SearchAsync(ModpackQuery q, CancellationToken ct);
    Task<IReadOnlyList<ModpackVersion>> GetVersionsAsync(
        string projectId, string? mcVersion, string? loader, CancellationToken ct);
    Task<ModpackPlan> ResolveAsync(string projectId, string versionId, CancellationToken ct);
}

public sealed record ModpackQuery(
    string? Text, string? McVersion, string? Loader,
    int Offset, int Limit, ModpackSort Sort);

public enum ModpackSort { Relevance, Downloads, Follows, Newest, Updated }
```

```csharp
public sealed record ModpackSummary(
    string Provider, string ProjectId, string Slug, string Title, string Description,
    IReadOnlyList<string> Categories, long Downloads, long Follows,
    string? IconUrl, DateTimeOffset UpdatedAt, string? LatestVersionId,
    bool ClientSupported, bool ServerSupported);
```

```csharp
public sealed record ModpackPlan(
    string Format,          // modrinth / curseforge / local
    string Name, string PackVersion,
    string McVersion, string Loader, string LoaderVersion,
    IReadOnlyList<PackFile> Files,
    IReadOnlyList<string> Overrides,
    string ArchivePath);

public sealed record PackFile(string Path, string Url, string Sha1, long Size);
```

UI 只认 `ModpackSummary` / `ModpackPlan`，不认任何 provider 的原始 JSON。

## 2. 本地格式检测

顺序固定，**不能调换**：

1. 含 `modrinth.index.json` → Modrinth `.mrpack`
2. 含 `manifest.json` 且带 `minecraft` + `files` → CurseForge
3. 含 HMCL/PCL 的导出结构 → `local`
4. 都不是 → 抛 `UnsupportedPackException`，文案里列出支持的三种

顺序错了会把 HMCL 包误判成 CurseForge（HMCL 导出包里也可能有 `manifest.json`）。

## 3. Modrinth

Base：`https://api.modrinth.com/v2`

| 用途 | 请求 |
|---|---|
| 搜索 | `GET /search?query=&limit=&offset=&index=relevance&facets=…` |
| 项目 | `GET /project/{id\|slug}` |
| 版本列表 | `GET /project/{id\|slug}/version?game_versions=["1.20.1"]&loaders=["forge"]` |
| 单版本 | `GET /version/{id}` |

`facets` 是 **JSON 字符串**，外层数组是 AND，内层是 OR：

```json
[["project_type:modpack"],["versions:1.20.1"],["categories:forge"]]
```

要点：

- 分页总数在 `total_hits`，不是 `hits.Count`。
- 下载文件取 `files[]` 里 `primary: true`，没有就取第一个。
- **必须带自定义 User-Agent**，格式 `a2cr-launcher/<ver> (+repo url)`。Modrinth 明确要求。
- 内存缓存 + 请求合并：搜索框输入要做防抖（≥300ms），不要每敲一个字打一次。
- `.mrpack` 解析：`modrinth.index.json` 的 `dependencies` 里 `minecraft` 给版本，`fabric-loader` / `quilt-loader` / `forge` / `neoforge` 给加载器；`files[].env.client == "unsupported"` 的要跳过；`overrides` 和 `client-overrides` 都算覆盖目录。

## 4. CurseForge

CurseForge 没有免 key 的官方路径，所以做成**三条可切换的路**，默认走镜像：

| 路径 | 何时用 | 说明 |
|---|---|---|
| API 镜像 | 默认 | 社区镜像（`mod.mcimirror.top`）。地址集中在常量类里，可配置，不要散落 |
| 官方 API | 用户自己填了 key | 用户自带的 key 只存本地，不进日志、不上传 |
| 关闭 | 只做本地导入 | 搜索页不显示 CurseForge 结果 |

### 必须带自己的 UA

所有镜像 / 官方请求都带 `a2cr-launcher/<ver> (+repo url)`。

- 镜像站靠 UA 区分调用方，出问题时也才能找到你；
- **不要冒充其他启动器的 UA**。有些启动器这么干是为了拿更快的线路，但那是最容易被
  拉黑的做法，而且会把别人的信誉算到你头上。

### 规则

- 解析优先级：API（镜像或官方）→ 失败标记。单个文件失败**不阻断**整个导入：
  跳过并记入 `missing-files.txt`（每行 `project=<id> file=<id> <原因>`），重新导入会再试一次。
- 已知 `fileId` 时可以直接拼 CDN 直链作为**下载**兜底
  （`https://mediafilez.forgecdn.net/files/{id/1000}/{id%1000}/{文件名}`）。
  这条只用于下载，不用于查元数据——它不告诉你文件名，也不保证还有效。
- `.zip` 结尾的文件按项目页分类决定放 `mods/` 还是 `resourcepacks/`。
- 搜索页：来源不可用时显示"暂不可用"，**不要转圈、不要自动重试到超时**。
- **不做网页抓取兜底**（原来的 `r.jina.ai` + 正则抓 `File name`）：靠正则解析第三方渲染
  页面，对方改一次就断，而且容易被当成爬虫。宁可少一个兜底，也不给用户一个偶发失败的功能。

## 5. 本地包（HMCL / PCL）

- 没有清单文件，只能整包解压。
- 识别版本与加载器靠目录结构 + 文件名嗅探。
- **`format == local` 不生成可更新的托管清单**：`manifest` 里这些文件记为 `pack` 但不参与"更新时删除"（没有清单就无法判断新旧归属）。
- 解压时必须挡 `../` 逃逸：解析后路径必须仍在实例目录内。

## 6. 导入阶段

```csharp
public enum ImportStage { Parse, Resolve, Vanilla, Loader, Extract, Files, Done }
public readonly record struct ImportProgress(
    ImportStage Stage, int Done, int Total, string Detail);
```

| 阶段 | 进度语义 |
|---|---|
| `Parse` | 0/1 → 1/1 |
| `Resolve` | CurseForge 文件地址解析数量 |
| `Vanilla` | 原版下载文件数 |
| `Loader` | 0/0（安装器没有细粒度进度，只报开始/完成） |
| `Extract` | 0/0 |
| `Files` | 整合包文件下载数 |
| `Done` | 1/1 |

UI 的文案表必须覆盖全部枚举值，新增阶段要同步加文案。

加载器安装器（Forge/NeoForge）运行期间**无法取消**：`CancellationToken` 只能等到安装器进程退出。这一点要在 UI 上说明，不要给用户"点了取消但没反应"的错觉。

## 7. 兼容性门禁

搜索和"同步"都需要判断兼容组：`(mc_version, loader, loader_version)`。

- 搜索整合包时，用户已选实例的版本/加载器作为默认筛选。
- 搜索资源包/光影包时按 `mc_version` 过滤（光影不依赖加载器）。
- Mod 必须有 `client_side` 支持才能装进客户端；`server_side` 只用来显示角标。

## 8. 测试点

- 三种格式各一个真实样本，`detect` 结果正确。
- `.mrpack` 里 `env.client == unsupported` 的文件被排除。
- CurseForge 某个文件镜像查不到 → 其余文件继续，`missing-files.txt` 生成。
- 镜像整体不可用 → 导入给出可读错误，不是空指针。
- 解压 `../` 路径被拒绝。
