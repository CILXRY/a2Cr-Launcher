## 1. Golden 数据

### 1.1 怎么来

v2 不复用 v1 的代码，但**复用 v1 的行为**：迁移初期用 `legacy/v1-python/` 跑一次导出脚本，
把结果提交进仓库。

```text
tools/export-golden.py           ← 一次性工具，跑完可删
tests/fixtures/<version_id>/     ← 提交进仓库，CI 不依赖 Python
```

CI 只读 fixtures：不联网、不运行 Python。

### 1.2 版本样本

**v2.0 只支持 1.13 及以后**（理由见 [`06-启动链路.md`](06-启动链路.md) 第 5 节），
所以样本里**不要放 1.12.2 及以前**——那会导出一个 v2 根本不该支持的 golden。

| 样本 | 覆盖点 |
|---|---|
| 1.16.5 原版 | 较早的现代 `arguments`、libraries 结构 |
| 1.20.1 原版 | 标准现代样本 |
| 1.20.1 + Forge | `inheritsFrom`、processors |
| 1.21.1 + NeoForge | `bootstraplauncher`（**不加 client.jar**）、Java 21 |
| 1.21.1 + Fabric | 只有 maven 坐标、没有 `downloads.artifact` |
| 26.x 原版 | Java 25、log4j XML 控制台输出 |

每个样本导出：

- 合并后的完整 meta；
- 规则求值后的 libraries（**含顺序**）；
- 完整 argv；
- classpath 字符串；
- 规则判定矩阵（含 `features` 组合）。

### 1.3 断言方式

- argv 比较前先规范化：路径分隔符统一、盘符大小写统一；**参数顺序必须完全一致**
  （顺序错了游戏可能也能跑，但出问题极难查）。
- 路径相关断言用占位符替换根目录，保证换机器也能跑。
- 规则矩阵用表驱动，一行一个用例。

### 1.4 配置文件样本

| 文件 | 样本 |
|---|---|
| `launcher.json` | 正常 / 缺字段 / 未知字段 / 非法值 / 带 BOM / 语法损坏 |
| `instance.json` | 正常 / 缺可选字段 / 带 BOM / 语法损坏 / `format` 过高 |
| `accounts.json` | 多账号 / 无选中 / 选中不存在 / 已过期 / token 失效 |
| `manifest.json` | 四种 `origin` 齐全 / 路径带反斜杠 / 重复路径 / 指向已消失的文件 |

### 1.5 整合包样本

三个真实包，体积大的裁剪成最小可识别样本：

- `.mrpack`（含 `client-overrides`）
- CurseForge `.zip`（含 `overrides`）
- HMCL 导出包

## 2. 单元测试覆盖底线

| 模块 | 必须有测试的点 |
|---|---|
| 下载 | 续传 / 416 / 忽略 Range 返回 200 / 取消保留 `.part` / 去重 / 早退 / **4xx 不重试** / 大小不符不计算哈希 |
| 规则 | 16 条判定矩阵 + `features` 组合 + 空规则 |
| 参数 | **未知占位符抛 `meta_incomplete`**（不是静默丢弃）/ Forge 是否加 `client.jar` |
| 合并 | `inheritsFrom` 覆盖顺序、环检测 |
| 路径 | `../` 逃逸拒绝；`A2CR_ROOT` 覆盖；长路径 |
| 清单 | `origin` 语义；更新只清理 `pack` 且哈希未变 |
| 账号 | 离线 UUID 已知值；令牌续期边界（提前 5 分钟） |
| 存储 | 克隆后互不影响；**GC 按 manifest 引用**（不是文件系统链接数）；只读时替换 |
| 设置 | 非法值回退；未知字段保留；并发钳到 1–16 |
| 错误 | 每个 `Code` 都有对应用例；取消永远不变成失败 |

## 3. 真实回归（人工，每次发布前）

1. 干净根目录 → 自动建目录、显示空状态、失败时有兜底页（v1 issue #4）。
2. 安装并启动 1.20.1 原版，正常进主菜单。
3. 安装 Forge 1.20.1 并启动。
4. 安装 NeoForge 1.21.1 并启动。
5. 导入真实整合包；再导入新版本（更新），确认：玩家自己的 mod 还在、包删掉的被清理、
   玩家改过的托管文件被保留。
6. 克隆实例 → 改其中一个的 mod → 另一个不受影响；实际占用没有翻倍。
7. 正版账号启动，进 online-mode 服务器。
8. 删除实例 → `.trash` 里能找到 → 移回去能重新识别。
9. 深色 / 浅色主题切换，五个页面都不出现布局错误。
10. 中文 Windows 下游戏日志不乱码（含 log4j XML 还原）。
11. 断网启动：元数据已缓存时仍能启动。
12. Java 缺失 / 指定路径失效：给出可读提示，不静默换版本。
13. **存档池**（开启后）：同组两个实例共享世界；在游戏里删掉世界只解除引用；
    另一个独占实例不受影响。
14. `doctor` 在一台干净机器上跑通（无 Java 时也要正常报告）。
15. 限速 200 KB/s 下下载 20 MB 文件，不被误判读超时。
16. 实例名和工作目录含中文与空格；数据目录在 OneDrive 下时给出硬链接警告。
17. 强杀进程模拟崩溃 → 下次启动提示"上次异常退出"。

## 4. CI 闸门

| 检查 | 失败条件 |
|---|---|
| 构建 | `TreatWarningsAsErrors` 下有任何警告 |
| 单测 | 任何一个失败 |
| Golden | argv / 合并结果 / 规则矩阵有任何差异 |
| 分层 | `a2Cr.Core` 里出现 `Console.Write*` 或直接写文件（`IFileStore` 实现除外） |
| CLI smoke | `--help` 退出码非 0 |
| JSON 信封 | `version --json` 的 stdout 不是单个顶层对象，或缺 `ok` 字段 |
| doctor | 在没有 Java 的 CI 机器上退出码不是 0 |
| 打包体积 | 单文件产物 > 60 MB，或输出文件数 > 20 |
| 敏感信息 | 测试日志里出现 `access_token` / `refresh_token` / `curseforge_key` 的真实值 |

最后两条是防历史问题复发：v0.3.2 的发布包里混进了 33 MB 的开发工具 `pyrefly`，
占了整个包的 25%；v1 也曾在日志里留下过 token。

## 6. 修 bug 的规矩

**每个修掉的 bug 都要在 `tests/` 里补一条能复现它的用例**，否则不算修完。

理由很实际：v1 的冒烟测试里有一半用例是"某次踩坑之后补的"，包括
`services.DownloadCancelled` 的重新导出、`instance._meta_define` 把 folder 写成元组、
`inheritFrom` 合并顺序。这些都是"改一处、悄悄坏另一处"的典型，
没有用例就会反复。
