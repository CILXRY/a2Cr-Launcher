## 1. Golden 数据

### 1.1 怎么来

v2 不复用 v1 的代码，但**复用 v1 的行为**：在迁移初期用现有的 Python 版跑一次导出脚本，把结果提交进仓库。

```text
tools/export-golden.py          ← 一次性工具，跑完即可删
tests/fixtures/<version_id>/    ← 提交进仓库，CI 不依赖 Python
```

CI 只读 fixtures，不联网、不运行 Python。

### 1.2 版本样本（6 个）

| 样本 | 覆盖点 |
|---|---|
| 1.20.1 原版 | 现代 `arguments` 对象格式 |
| 1.7.10 + Forge | 老式 `minecraftArguments`、`inheritsFrom`、natives 解压 |
| 1.12.2 + Forge | 老式安装机制、Java 8 |
| 1.20.1 + Forge | 新 processors、`BootstrapLauncher`（**不加 client.jar**） |
| 1.21.1 + NeoForge | `bootstraplauncher`、Java 21 |
| 1.21.x + Fabric | 只有 maven 坐标、无 `downloads.artifact` |

每个样本导出：

- 合并后的完整 meta
- `allowed_libraries` 的结果（**含顺序**）
- 完整 argv
- classpath 字符串
- 规则判定矩阵（含 `features` 的组合）

### 1.3 断言方式

- argv 比较前先规范化：路径分隔符统一 `\`、盘符大小写统一、参数顺序**必须完全一致**（顺序错了游戏可能能跑，但出问题极难查）。
- 规则矩阵用表驱动测试，一行一个用例。
- 路径相关的断言用占位符替换根目录，保证换机器也能跑。

## 3. 真实回归（人工，每次发布前）

1. 干净根目录 → 启动器能创建全部目录并显示空状态（v1 issue #4）。
2. 安装并启动 1.20.1 原版，正常进主菜单。
3. 安装 Forge 1.20.1 并启动。
4. 安装 NeoForge 1.21.1 并启动。
5. 导入一个真实整合包；再导入它的新版本（更新），确认：
   - 玩家自己放的 mod 还在；
   - 整合包删掉的 mod 被清理；
   - 玩家改过的托管文件被保留。
6. 克隆实例 → 改其中一个的 mod → 另一个不受影响；磁盘实际占用没有翻倍。
7. 用正版账号启动，进入 online-mode 服务器。
8. 删除实例 → `.trash` 里能找到 → 移回去能重新识别。
9. 深色/浅色主题切换，五个页面都不出现布局错误。
10. 中文 Windows 下游戏日志不乱码。

## 4. CI 闸门

| 检查 | 失败条件 |
|---|---|
| 构建 | `TreatWarningsAsErrors` 下有任何警告 |
| 单测 | 任何一个失败 |
| Golden | argv / 合并结果 / 规则矩阵有任何差异 |
| 分层 | `A2cr.Core` 里出现 `Console.Write*` 或直接写文件（`IFileStore` 实现除外） |
| CLI smoke | `--help` 退出码非 0 |
| 打包体积 | 单文件产物 > 60 MB，或输出文件数 > 20 |
| 敏感信息 | 测试日志里出现 `access_token` / `refresh_token` 字样 |

最后两条是防止历史问题复发：v0.3.2 的发布包里混进了 33 MB 的开发工具 `pyrefly`，占了整个包的 25%。
