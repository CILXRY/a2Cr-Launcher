## 1. `instance.json`

只放元信息。文件清单拆到 `manifest.json`，避免随着 mod 数量膨胀。

```json
{
  "format": 1,
  "name": "机械动力整合包",
  "mc_version": "1.20.1",
  "version_id": "forge-47.2.0-1.20.1",
  "loader": { "type": "forge", "version": "47.2.0" },
  "source": { "format": "curseforge", "file": "D:\\packs\\craft.zip", "pack_version": "1.2" },
  "created_at": "2026-11-20T03:04:05",
  "last_played": "2026-11-21T10:00:00",
  "cloned_from": null,
  "template": "default"
}
```

| 字段 | 规则 |
|---|---|
| `format` | schema 版本，从 1 开始；解析时遇到更高版本要拒绝并提示 |
| `name` | 显示名，可重复，可中文 |
| `loader.type` | `vanilla` / `fabric` / `quilt` / `forge` / `neoforge` |
| `version_id` | 启动时用的版本目录名，可能指向 `shared/versions/<id>` |
| `source.file` | 整合包原始绝对路径；用于"同一个包重复导入 → 续跑同一实例" |
| `source.format` | `modrinth` / `curseforge` / `local` |
| `created_at` / `last_played` | 本地时间 ISO 8601，秒级，**不带时区** |
| `last_played` | 只在**进程创建成功后**写；启动失败不许污染排序 |
| `cloned_from` | 克隆来源的目录名；用于 UI 显示，不参与任何逻辑 |

读取要求：

- `utf-8-sig`（兼容记事本 BOM）；JSON 损坏或不是对象 → 视为不存在，不要让界面崩。
- 缺失的可选字段补默认值；未知字段原样保留（向前兼容）。
- 写入一律临时文件 + 原子替换。

## 2. `manifest.json`

记录"实例里每个文件的来源"。所有依赖文件归属的功能（更新、重置、清理、去重、同步）都只查这里。

```json
{
  "format": 1,
  "files": [
    { "path": "mods/create-1.20.1.jar", "sha1": "…", "origin": "pack",     "sha1OnInstall": "…" },
    { "path": "options.txt",            "sha1": "…", "origin": "template", "template": "default" },
    { "path": "saves/我的世界",          "sha1": null, "origin": "user" },
    { "path": "mods/jei.jar",           "sha1": "…", "origin": "shared",   "group": "<group id>" }
  ]
}
```

| `origin` | 含义 | 谁能改/删 |
|---|---|---|
| `pack` | 整合包清单里的文件（下载来的） | 更新整合包时可删（哈希未变才删） |
| `template` | 新建实例时从模板复制的 | 重置模板时可覆盖 |
| `user` | 玩家自己放进去的 | **永不自动删除** |
| `pool` | 从池子链接进来的（mod / 资源包 / 光影） | 池里没有对应文件时，由对账移除链接 |

规则：

- `path` 一律用相对实例目录的**正斜杠**形式，比较前统一大小写（Windows）。
- `sha1` 是当前已知哈希；`sha1OnInstall` 是安装时的哈希，用来判断"玩家改过没有"。
- 没有 URL 的文件（模板、本地包解压出来的）没有 `sha1OnInstall` 时，以 `sha1` 为准。
- **不在 manifest 里出现的文件，一律当作 `user`**。这条保证了"手工丢进 mods 的 jar"永远不会被清理。
- manifest 由文件存储层在每次写入时维护（见 `04-文件存储.md`），不要由调用方手工拼。

## 3. 新建实例流程

1. 解析整合包 → 得到 `mc_version / loader / loader_version / files / overrides`。
2. 安装原版到 `shared/versions/<mc_version>`（已装则跳过）。
3. 安装加载器，得到 `version_id`。
4. 生成目录名（`02-目录结构.md` 第 4 节）。
5. 建目录，应用模板（`origin=template`）。
6. 解压 overrides（记 `origin=pack`，因为没有独立下载 URL，`sha1OnInstall` 用解压后哈希）。
7. 下载文件（`origin=pack`）。
8. 写 `instance.json` + `manifest.json`。

步骤 2、3 可以在任何时刻失败并重跑；已经下载的文件靠哈希跳过。**整个流程必须幂等。**

## 4. 更新整合包

```
只处理 origin == pack 的条目，且当前哈希 == sha1OnInstall 才删除
```

顺序必须是：**先下载新文件成功 → 再清理旧文件**。反过来会在失败时两头空。

`format == local`（HMCL/PCL 导出包）不做删除：这种包没有清单文件，无法判断哪些文件归整合包托管，只能覆盖。

## 5. 克隆实例

### 5.1 目的

克隆要**接近零成本**。池子模型下这件事变得很简单：

**克隆 = 建目录 + 写元数据 + 跑一次对账（`02-目录结构.md` 第 5.2 节）。**

因为 mod / 资源包 / 光影本来就在池子里，实例只需要建立链接，不需要从来源实例
逐个文件复制，也不需要比较两边哈希。

不使用目录符号链接（权限、备份、删除都会出问题）；`saves` 是唯一的例外，见 5.2。

### 5.2 各类内容怎么处理

| 内容 | 方式 | 原因 |
|---|---|---|
| `mods/**` `resourcepacks/**` `shaderpacks/**` | **交给对账建硬链接** | 本来就在池里，独立于任何来源实例 |
| `config/**` `options.txt` `servers.dat` `*.dat` | **复制** | 会被游戏和 mod 频繁原地重写 |
| `saves/**` | **目录联接**到 `pool/saves/<mc_version>` | 同版本共享存档；必须检测并发占用 |
| `logs/**` `crash-reports/**` | 跳过（建空目录） | 复制日志没有意义 |
| `instance.json` | 新写 | 新的 `name` / `created_at` / `cloned_from` |
| `manifest.json` | 重新生成 | 由对账过程写出，不复制来源实例的清单 |

克隆时**不复制**来源实例里 `origin=user` 的文件——那是别人自己放的，不属于这个实例。
需要带过去的话，让用户从池子里重新加。

### 5.3 算法

1. 目标目录建在 `instances/.tmp-<random>`，不要在最终名字上边建边写。
2. 写 `instance.json`（`cloned_from` 指向来源目录名）。
3. 复制会被改写的私有文件（5.2 里标"复制"的行）。
4. 建 `saves` 联接，指向来源实例所属的存档桶。
5. 跑一次对账（`02-目录结构.md` 5.2），把池子里的内容链接进来；对账顺带写出 `manifest.json`。
6. 全部完成后整体 rename 到最终目录。
7. 失败时删掉 `.tmp-*`，不留半个实例。

### 5.4 硬链接的前提

1. **同分区**：池子和实例在同一个根目录下，正常不会跨盘；跨卷时对账退化为复制，
   并在结果里报告降级数量（不影响正确性，只影响空间）。
2. **目标文件永远不能被原地覆盖**（见 `04-文件存储.md` 的写入纪律）。
   守住这条，实例里的文件才是标准 copy-on-write 语义。

### 5.5 磁盘占用

UI 上的"占用"必须区分两个数：

- 逻辑大小：目录内所有文件大小之和。
- 实际占用：按 `(volume, fileId)` 去重后的和（硬链接只算一次）。

两个克隆各显示 2 GB、实际总共 2 GB 才是正确的展示方式。

## 6. 模板

- `templates/<id>/template.json` 描述名字、描述、适用版本范围。
- 应用模板 = 把模板内容导进池子（若池里已有同哈希则跳过），再跑对账链接进实例，
  `origin=template` + `template=<id>`。
- 模板里的 `options.txt` 等可变文件**只复制不链接**；资源包 / 光影包走池子，和其他实例共享。
- 重置模板只影响 `origin == template` 的条目。

## 7. 删除实例

- 移到 `.trash/<folder>-<yyyyMMdd-HHmmss>`，不直接删。
- 只允许操作 `instances` 下的一级目录；解析后父目录必须等于 `instances` 根，拒绝 `../`。
- v2.1 起，移动后触发对象库 GC（见 `04-文件存储.md`）。

## 8. 实例级设置覆盖

实例可以覆盖全局设置里的几项，规则是**实例优先、没写就继承全局**：

```json
"overrides": {
  "max_memory": "8G",
  "jvm_args": "-XX:+UseG1GC",
  "java_major": 21
}
```

| 键 | 说明 |
|---|---|
| `max_memory` | 这个实例的内存上限；不写 = 用 `launcher.json` 的 `launch.max_memory` |
| `jvm_args` | 追加到这个实例的 JVM 参数；不写 = 用全局 |
| `java_major` | 指定要哪个**主版本**的 Java；具体路径仍由全局设置和自动发现解析 |

约束：

- 只允许覆盖**这张表里的键**。其它设置（下载、界面、日志）是启动器级的，不允许按实例覆盖。
- 覆盖项写错（比如 `max_memory: "abc"`）时回退全局值，并在实例详情里提示，不要让启动失败。
- 实例被克隆时，`overrides` 一并复制过去。
- 全局设置变化**不会**改动已有实例的覆盖项——覆盖是显式写下的决定。

这条让"这个整合包要 8G、别的用 4G"不用去改全局设置。
