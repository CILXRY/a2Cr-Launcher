从"版本 id"到"Java 进程跑起来"的全过程。这部分是启动器最容易出错的地方，所有规则必须逐条实现，不要自行简化。

## 1. 版本元数据

- 存放：`shared/versions/<id>/<id>.json`，内容是**完整**版本 JSON（`libraries` / `arguments` / `logging` / `downloads` / `assetIndex` 缺一不可）。
- 文件名就是 `<id>.json`，不是 `meta.json`（v1 的注释写错过，别延续）。
- 本地存在且 `id` 匹配 → 直接用；`refresh: true`（安装时）→ 强制从网络取并覆盖本地。
- 版本列表缓存：`shared/cache/version_manifest_v2.json`；只有 `latest` 字段变化才覆盖。

```csharp
Task<VersionMeta> GetVersionMetaAsync(string id, bool refresh = false, CancellationToken ct);
```

## 2. `inheritsFrom` 合并

加载器版本（Forge/Fabric）只写差异，需要与父版本合并：

- `libraries`：父在前，子在后；同一 `group:artifact` 以子版本覆盖父版本，**顺序不能乱**（classpath 顺序影响类加载）。
- `arguments`：父子的 `game` / `jvm` 数组都要保留，子在后。
- `mainClass` / `assetIndex` / `downloads` / `jar`：子有就用子。
- 合并后必须保留 `_baseVersion`（父版本 id），拼 classpath 和 client.jar 路径时要用。
- 合并结果不落盘，每次现算（父版本更新后能自动生效）。

## 3. 规则评估

Minecraft 的 `rules` 是 allow/disallow 列表，按顺序匹配，**后面的覆盖前面的**，最后一条匹配的 `action` 决定结果。

支持的维度：

| 维度 | 匹配方式 |
|---|---|
| `os.name` | `windows` / `osx` / `linux` |
| `os.arch` | `x86` / `x86_64` / `arm64` |
| `os.version` | 正则匹配（基本不用，支持即可） |
| `features` | 布尔集合：`is_demo_user` / `has_custom_resolution` / `has_quick_plays_support` / `is_quick_play_*` |

没有规则 → 默认允许。`action: allow` + 不匹配 → 不允许。必须用 v1 的判定矩阵做回归（见 `11-验收与回归.md`）。

## 4. 运行库与 natives

### 4.1 路径解析

两种写法都要支持：

1. 原版：`downloads.artifact.path` 直接用。
2. Fabric/Forge：只给 maven 坐标 `group:artifact:version[:classifier]`，要自己拼：
   `group` 的点换成 `/` + `<artifact>/<version>/<artifact>-<version>[-<classifier>].jar`。

### 4.2 下载地址

- 有 `downloads.artifact.url` → 用它。
- 否则 `library.url`（默认 `https://libraries.minecraft.net/`）+ 相对路径。

### 4.3 natives（1.19 以前的老版本）

- `downloads.classifiers` 里带 `natives-windows` 等键的，要解压到 `shared/versions/<id>/natives/`。
- 解压前确认 `natives/{java,jna,lwjgl,netty}` 子目录存在（LWJGL/JNA/Netty 会往里解压）。
- JVM 参数 `-Djava.library.path=<natives 目录>`。
- 新版本（1.19+）natives 已经打进普通 jar，不需要额外处理。

## 5. 启动参数

### 5.1 模板替换

`arguments.game` / `arguments.jvm` 里的字符串按 `${key}` 替换，替换表：

| key | 值 |
|---|---|
| `auth_player_name` | 账号名 |
| `version_name` | 版本 id |
| `game_directory` | 实例目录 |
| `assets_root` | `shared/assets` |
| `assets_index_name` | `assetIndex.id` |
| `auth_uuid` | 账号 UUID（**不能**用 `name` 现算） |
| `auth_access_token` | 账号 token；离线固定 `"0"` |
| `user_type` | 在线 `"msa"`，离线 `"legacy"` |
| `auth_xuid` / `clientid` | 在线账号的对应字段，离线为空 |
| `version_type` | 版本 JSON 的 `type` |
| `natives_directory` | 见 4.3 |
| `library_directory` | `shared/libraries` |
| `classpath_separator` | `;`（Windows） |
| `classpath` | 见 5.2 |
| `launcher_name` / `launcher_version` | `a2cr-launcher` / 程序版本 |
| `max_memory` | 用户设置 |

- **未识别的变量必须丢弃整条参数**，不能留下字面量 `${foo}` 传给游戏（会直接崩）。
- `arguments.jvm` 里有 `-Dos.name=Windows` 这类写死值，原样保留。

### 5.2 classpath

顺序：先 libraries（按合并后的顺序），最后才是 client.jar。

**例外**：`mainClass` 含 `bootstraplauncher`（新 Forge/NeoForge）时**不加 client.jar**。
那种启动器会自己把打过补丁的 jar 加进模块层，再加原版 client.jar 会出现两个导出同一模块的 jar，模块解析直接失败。

### 5.3 内存

`-Xmx<max_memory>` 由启动器注入，不依赖版本 JSON。

## 6. Java 发现

- 支持从设置里手动指定（目录或可执行文件）。
- 自动扫描：`JAVA_HOME`、PATH、`Program Files\Java`、`Program Files\Eclipse Adoptium`、`Program Files\Microsoft`、注册表 `SOFTWARE\JavaSoft`、启动器自己下载过的运行时（如果有）。
- 必须能报告每个候选的**版本号**和 **位数**，UI 上要展示，选择错误时才能解释。

### 版本要求

| 游戏版本 | Java |
|---|---|
| ≤ 1.12.2 | 8（必须，高版本会崩） |
| 1.13 – 1.16.5 | 8 或 11 |
| 1.17 – 1.20.4 | 17 |
| 1.20.5+ | 21 |

规则：优先选满足要求的最低版本；找不到满足要求的就明确报错，**不要拿 21 去开 1.12.2**。

## 7. 启动前检查

在创建进程前必须做：

1. 实例目录存在（不存在就建）。
2. `natives` 子目录存在。
3. 解析出的 classpath 里每个文件都存在——缺了就抛 `MissingFilesException`，列出缺失项。
   不做这一步，用户只会看到一堆 `ClassNotFoundException`。

## 8. 进程与日志

- 工作目录 = 实例目录（**必须**，mod 的相对路径依赖它）。
- 标准输出/标准错误都要接管，按行回调给 UI。
- **编码必须显式设为 UTF-8**。Java 输出在中文 Windows 上默认按 GBK 解会乱码甚至抛异常。
- 进程创建成功后回调一次 `onProcess(proc)`，UI 用它实现"停止游戏"。
- 返回退出码；非 0 时把最后的日志片段一并带回，方便用户截图反馈。

## 9. 测试点

- 6 个样本版本的完整 argv 与 Python 版逐字符一致（见 `11-验收与回归.md`）。
- Forge（新）不包含 client.jar；Fabric 包含。
- 未知变量被整条丢弃。
- 1.7.10 老格式（`minecraftArguments` 字符串）也要能启动。
- 中文 Windows 下日志不乱码。
