# 启动链路

> **完善中**：未定稿，`【待确认】` 处需要拍板；和 [`产品想法.md`](../产品想法.md) 冲突时改本文。

## 1. 一条链路

```text
版本 id
  → 读 cache/versions/<id>/<id>.json（缺则下载）
  → 沿 inheritsFrom 递归合并，得到完整 meta
  → 求值 libraries / arguments 里的 rules
  → 拼出完整 argv
  → 选 Java（设置里指定的优先，否则按 majorVersion 找）
  → 建 natives 目录
  → 启动进程，转发日志
  → 返回退出码
```

v1（`legacy/v1-python/src/a2cr_launcher/launch/`）已经把这条件链路跑通过，
**这一段是移植，不是重新设计**。下面写的都是 v1 里已经验证过的行为。

## 2. 版本元数据

- 位置：`cache/versions/<id>/<id>.json`，必须是**完整**的版本 JSON——
  含 `libraries`、`arguments`、`logging`、`downloads`、`assetIndex`，拼参数时每一段都要用。
- 缺失或损坏 → 从 Mojang 下载；已经有就不重复下载（`refresh` 才强制）。
- 没有任何可用的参数结构（既没有 `arguments` 也没有 `minecraftArguments`）→
  明确报"版本信息不完整"，不要让它跑到拼参数一半才炸。

## 3. `inheritsFrom` 合并

加载器版本（Fabric / Quilt / Forge / NeoForge）都是"子版本 + `inheritsFrom` 指向原版"。
合并规则（照 v1 实现，已验证）：

| 字段 | 规则 |
|---|---|
| `libraries` | 父在前、子在后；同名覆盖（key 用 `name`，没有则用 `downloads.artifact.path`） |
| `arguments` | 按 `jvm` / `game` 分别拼接，父在前、子在后 |
| `id` `type` `mainClass` | 子版本优先，缺了用父版本 |
| `logging` `javaVersion` | 子版本有才覆盖 |
| `minecraftArguments` | 子版本有才覆盖（老格式） |
| `_baseVersion` | 合并后写入最底层的原版版本号，后面拼 classpath 用 |

- 递归合并，**必须带环检测**：`a → b → a` 要报错，不能栈溢出。
- 合并完删掉 `inheritsFrom`，避免下游误判。

## 4. 规则求值

语义（v1 的 16 条用例已经把它钉死，移植时把这些用例原样搬过来）：

1. 空规则集 → **允许**。
2. 从**后往前**扫，第一条匹配的规则决定结果（`allow` / `disallow`）。
3. 一条都不匹配 → **不允许**（"没人授权"不等于"允许"）。
4. 匹配条件：`os.name`、`os.arch`、`features.*`；调用方没给 `features` 时按"未启用"处理，
   不能崩。

## 5. 参数拼装

顺序固定：`java` → JVM 参数 → logging 参数 → `mainClass` → 游戏参数。

占位符表（值来自实例元数据和路径）：

```text
auth_player_name  version_name   game_directory  assets_root  assets_index_name
auth_uuid  auth_access_token  user_type  clientid  auth_xuid
natives_directory  library_directory  classpath  classpath_separator
launcher_name  launcher_version  version_type  max_memory
```

要点：

- 内存写成 `-Xmx<max_memory>` 和 `-Xms<max_memory>`（两处同值，v1 的做法，别自作聪明分开）。
- **未知占位符不能静默跳过**：替换失败要转成"版本信息不完整"的可读错误，
  否则会拼出一条缺参数的命令行，游戏启动后才莫名其妙地失败。
- **Forge / NeoForge 特例**：`mainClass` 里含 `bootstraplauncher` 时**不能**把原版
  `client.jar` 加进 classpath。BootstrapLauncher 会自己把打过补丁的 jar 加进模块层，
  再加一份会出现两个导出同一包的模块，模块解析直接失败。
- 1.13 以前的版本只有 `minecraftArguments`（纯字符串）→ v2.0 **明确不支持**，
  给出可读提示，不要半启动。

## 6. Java 选择

扫描顺序（照 v1）：

1. 设置里手动指定的路径 / 目录；
2. `JAVA_HOME`；
3. `Program Files` 下的常见厂商目录（Zulu、Java、Eclipse Adoptium、Microsoft、
   BellSoft、Amazon Corretto、Semeru）；
4. 官方启动器下载的运行时（`%APPDATA%\.minecraft\runtime`、
   微软商店版的 `%LOCALAPPDATA%\Packages\Microsoft.4297127D64EC6_...\runtime`）；
5. `PATH` 里的 `java`。

版本探测：优先读安装目录里的 `release` 文件（`JAVA_VERSION=`），读不到再执行
`java -version` 解析 stderr。**`1.8.0_xxx` 这种老写法要归一到主版本 8。**

选择策略：在"主版本 ≥ 版本 JSON 要求的 `javaVersion.majorVersion`"里挑**最接近**的那个。

- 手动指定的路径失效时**明确报错**，不要悄悄换一个 Java 启动——参数会和玩家预期不一致。
- 一个都找不到时，错误信息要能照着做（"安装 Java X，或把 JAVA_HOME 指向已有安装"）。

## 7. 进程与日志

- 启动：`stdout` 与 `stderr` **合并**到一条流，按行转 UTF-8（坏字节替换，不能让一个
  emoji 把启动器搞崩）。
- 进程创建后**立刻**通知界面（回调 `on_process`），这样"运行中"状态不用等第一行日志。
  回调本身抛异常不能影响"启动成功/失败"的判断。
- **Minecraft 26.x 的坑**：日志配置换成了 log4j XML（`LegacyXMLLayout`），控制台输出是
  `<log4j:Event ...>` 一段一段的 XML。必须聚块还原成
  `[HH:MM:SS] [线程/级别]: 消息`，ERROR / FATAL 附带最多 12 行堆栈。
  v1 的 `process.py` 里有现成的正则和阈值，直接照搬。
- 控制台编码兜底：中文 Windows 的控制台是 GBK，写不出来的字符要替换（C# 里对应
  `Console.OutputEncoding`）。**统一转成 UTF-8 再输出**（已定），避免同一份日志在不同
  机器上两套编码。
- 退出码原样返回。**"启动失败"和"游戏自己异常退出"必须区分**：
  前者是启动器的错误（找不到 java、参数不全），后者只是退出码非零。

## 8. 启动前检查

- `natives` 目录必须存在（缺了就建）。
- classpath 里每个文件都要存在，缺了直接报"缺少 N 个运行库或客户端文件，请先安装"，
  不要让 Java 抛一堆 `ClassNotFound`。
- **默认只检查文件存在性，不校验哈希**（全量校验太慢）。需要时由实例打开
  `verify_on_launch` 做完整校验（见 `03-实例与清单.md` 第 8 节），UI 要提示"耗时较长"。

## 9. 验收

- **golden 对比**：同一个版本，v2 拼出来的 argv 必须和 v1 逐字符一致（v1 能直接打印命令行），
  这是移植阶段最省事的保险。
- 规则求值：v1 的 16 条用例全部通过。
- 真机：原版至少跑通两个版本（一个旧的、一个 26.x），能进主菜单。
- 断网：版本元数据已在 `cache` 时仍能启动（不依赖网络）。
- Java 缺失：给出可操作提示，不是堆栈。

## 10. 明确不做

- **不做 Java 自动下载**：v2.0 只发现、选择；下载运行时需要先定来源和磁盘占用。
- **不解析游戏输出做游戏内事件**（比如"进入世界"）：只做日志转发。
